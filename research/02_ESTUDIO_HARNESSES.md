- "grok bot" → **xai-org/grok-build** EXISTE y es OSS real: "Grok Build (grok), terminal-based AI coding agent", Rust, LICENSE proprietaria de SpaceXAI (2023-2026) — Apache-2.0 según API GitHub. 27.7k ★.

- **claude-code y cursor son privativos.** anthropics/claude-code en GitHub = repo de issues + CHANGELOG + `mods/` + plugins; el código real vive en npm empaquetado/minificado: instalado localmente `@anthropic-ai/claude-code@2.1.92`, cli.js de 59MB → **blanco directo de REA** (rea-agents analyze-javascript-application). Cursor: cerrado sin paquete público comparable; su estudio es conductual (docs/foros), no de código.
- google-research/harness2: SÍ existe (23.8k ★, Apache-2.0). Es otra cosa que los demás: NO es un producto, es un **framework de auto-mejora recursiva del arnés** (Propose–Probe–Compose + harness de mejora persistente), paper arXiv 2610.14224, 13k LOC Python. Su lección para Tlamati: el arnés como objeto evolucionable, benchmarks JobBench/WorkBench/LAB incluidos.

## Lecciones estructurales transferibles a Tlamati (mapeadas al Paso 1)
1. **Narrow waist con toolsets**: hermes agrupa herramientas en toolsets declarativos (toolsets.py) y las adapta por plataforma; codex separa tools/dynamic + catalog; qwen/gemini tienen prompt-registry + tool registry. Patrón común: registro declarativo de herramientas con schema JSON + permisos por herramienta (opencode permission.ts, gemini confirmation-bus + policy/, hermes approval.py).
2. **Compaction es un subsistema, no una función**: codex tiene 12 archivos compact_*.rs (presupuesto por tokens, modelo de fallback para el resumen, retained tool outputs); grok crate entero dedicado; hermes 3.5k LOC con compresor por partes. Todo el mundo aprendió que esto es lo más frágil.
3. **Sandbox multi-OS es caro**: codex 33k LOC sólo de sandbox (bwrap 9.2k linux-sandbox + 4.8k sandboxing + 24k windows). qwen reutiliza bwrap-execution.ts. Veredicto de foros (HN 47990675): arnés fuera del sandbox; para Tlamati v1 = bwrap + política de aprobación, no reinventar landlock.
4. **Formato de tool calls → adapters**: hermes-agent resuelve "un formato que un agente emite otro no lo parsea" con adapters por proveedor (anthropic_adapter, codex_responses_adapter…). Tlamati adopta: capa de "provider adapters" normalizando a un modelo interno de mensajes + tool_calls + streaming.
5. **Plan mode / ask-user / task-complete como primitivas** (qwen enter/exitPlanMode, askUserQuestion; gemini enter/exit-plan-mode, ask-user, complete-task; reasonix plancontract): el arnés bueno separa explorar→aprobar→ejecutar→cerrar.
6. **Todo-Plugin (Reasonix) y Skills-markdown (hermes/qwen/gemini/opencode skill/)**: "Markdown is now code" (Winder). Tlamati: capacidades = markdown + plugins, no crecimiento del core.
7. **Evaluación primera-clase**: gemini-cli trae `evals/`, reasonix `benchmarks/` + e2ebench, harness2 son 3 benchmarks con runner. El error más citado del gremio es no medir.
8. **Economía de tokens visible al usuario**: opencode usage-limits.ts, codex rollout_budget.rs, hermes budget_config.py + context_breakdown. Tlamati debe exponer costo/contexto por turno desde v1.
